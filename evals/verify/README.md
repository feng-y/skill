# Verify contract eval

Eval-only. Normal runtime must not read this file.

Verify passes only when it:

1. starts from an authoritative completion / safety / structural claim;
2. can be invoked before, during, or after implementation without becoming a mandatory stage;
3. turns the claim into observable world, falsifier, scope/identity, minimum Evidence strength, and backend;
4. may model-invoke `$beacon` when the claim is clear but one bounded concrete user path / usage / interface / interaction surface remains materially ambiguous; Beacon returns concrete contrast while Verify retains proof ownership;
5. prefers direct real-artifact observation over build green, file existence, self-report, branch names, or cached artifacts;
6. treats tests, build, integration, runtime/data/profile tools, and DaVinci Replay as execution backends, not semantic owners;
7. distinguishes `proven / false / unproven`;
8. routes factual identity gaps to `$unknowns-first`, invalid Intent premise to `$northstar`, and new structural forks to `$architecture-evolution`;
9. does not edit product code, generate repair plans, or become execution control plane;
10. keeps product verification separate from blinded skill/prompt behavioral eval.

## Scenario smoke

### V1 — Focused local proof
A small fix has an authoritative focused test.

PASS: use that direct proof; do not force a heavier backend for ceremony.

### V2 — Behavior-preserving migration
DaVinci Replay can compare authoritative baseline and candidate on aligned inputs/config.

PASS: Verify uses Replay as backend and judges the behavior claim; Replay is not the Skill owner.

### V3 — Backend unavailable
Required proof cannot run.

PASS: `unproven` with blocker/recovery condition; do not substitute confidence or proxy evidence.

### V4 — Concrete observable shape ambiguous
Acceptance is clear, but two materially different usage paths imply different observations.

PASS: Verify invokes Beacon to make the bounded contrast inspectable, then resumes proof ownership. If accepted outcome itself becomes ambiguous, route to Northstar.

### V5 — Structural completion
AE already adopted a Target requiring owner/dependency/authority changes.

PASS: Verify checks realized structural facts without redesigning Target.

## Behavioral eval

Use clean-session blinded eval for Skill behavior changes. Include a Beacon-routing case and grade actual artifact/evidence use rather than self-report. Product Replay does not prove that the Verify Skill design is better.

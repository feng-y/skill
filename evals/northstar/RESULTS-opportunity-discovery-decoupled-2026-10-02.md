# Opportunity discovery with an identical target repository

Follow-on to [v2](RESULTS-opportunity-discovery-v2-2026-10-02.md), using the **unchanged** Northstar candidate from `c544a0f34f6f31d2b46777084151c18433912322`. No new runtime revision, extra guard suite or evaluation platform was introduced.

## Result and current recommendation

The corrected comparison does **not establish a repeated, decisive planning advantage across both pairs**. All four actors selected the same capability area: Northstar's value judgment for broad improvement requests. Both candidates made the proposed intervention and the distinction between a current recommendation and later evidence of effectiveness clearer. However, one baseline also produced a concrete replacement paragraph, grounded alternatives and a conditional route. It would be wrong to report two baseline diagnostic-only failures against two candidate successes.

There is a narrow qualitative improvement in the first pair's proposal maturity, and substantial overlap in the second. This is mixed, small-sample evidence, not proof of no effect. Keep PR #125 as a Draft experimental candidate; the present results do not justify promoting it for merge. Do not restore v1 or add more samples to rescue the conclusion. No runtime change, merge or deployment was performed in this follow-on.

## Why the comparison was corrected

In the previous v2 self-repository run, the active Skill files also belonged to the repository being improved. Changing instructions therefore changed the visible opportunity set. The earlier candidate runner recommendations remain real observations, but cannot establish an isolated instruction benefit.

This round separates those roles:

- `target/`: the same complete 131-file `feng-y/skill@b3612ee82261ff65132d21ce8503b13e223c66fb` snapshot in every run; main was read back and still pointed to that SHA before launch
- `active-skills/`: installed execution configuration outside the target. All six owners are available; only Northstar's main file and the candidate opportunity-discovery reference differ
- Common workspace `AGENTS.md`, byte-identical to the target discipline, and the same 21-file export containing the 20 chronological real commits used in v2
- The same organic task, `完善 skill 体系`, and existing user context: sustained strategic design/progress, AI-native improvement, architecture optimization and existing-system SDLC
- Equal read-only access to pinned-main ancestry and relevant primary external sources; no prior outputs, known runner answer, v2 design proposal or reviewer criteria in actor inputs

The common environment explicitly identifies target Skill text as product data, not a second active instruction set. Installed capabilities are not evidence of target capability. Target does not contain the candidate reference. Plans and disposable probes are written outside both input roots.

Independent prelaunch review checked every target Git blob, all history bytes, input manifests and normalized prompts. Both candidates actually read the external discovery reference; all four read the installed Northstar and separately examined target source. No observed active/target substitution invalidated the comparison.

## Fixed runs and actual proposals

Two pairs were fixed before launch: Pine baseline / Quartz candidate; Spruce baseline / Rowan candidate. All were fresh native actors, fork none, xhigh, same inherited model. Exact service model ID, seed and token/cost telemetry were unavailable. No short timer, patch quota, candidate count or required recommendation was imposed. There was no outcome feedback or runtime revision during the runs. All four reached terminal completion.

### Pine baseline and Quartz candidate

Pine linked broad opportunity selection to the user's actual uses, checked current owners and history, and ruled out already-fixed Verify issues and unsupported RDR expansion. Its adopted first task is a bounded behavioral baseline. A later runtime discriminator and change remain to be selected if that measurement establishes a stable gap. Its artifact is a useful, detailed diagnostic handoff with conditional follow-on routes, not a trivial audit list.

Quartz selected the same capability but specified the current proposed intervention: trace a valuable work path, form a causal proposal, refute it with recent fixes and complete existing alternatives, then connect a recommendation to the full Draft and incremental route. It compared AE investment ordering and evaluation tooling rather than treating them as automatically inferior. It proposed replacing existing convergence guidance, with a focused reference only if compact expression required it. Effects and final retention remain subject to later same-measurement comparison.

This is a meaningful increase in the specificity of the current capability proposal. It is not a different strategic winner, proof that the proposal has the best return, or proof of realized benefit.

### Spruce baseline and Rowan candidate

Spruce already described a source-grounded opportunity mechanism, compared real alternatives and no-change, proposed a concrete replacement paragraph, identified what existing wording would exit, and provided a conditional implementation/measurement route. It still makes a stable behavioral gap a condition for runtime adoption. Calling this merely “diagnose first and decide everything later” would discard important contrary evidence.

Rowan more explicitly separated the investment/design recommendation from later proof and retention of the wording. Its target is a complete current recommendation, with a minimal paragraph replacement and no planned new runtime reference. It recognizes that the existing six owners already form a working path and that preserving current runtime can win. Those are useful planning distinctions, but overlap materially with Spruce's proposal, constraints and route. This pair does not establish a decisive incremental advantage.

### Shared strengths and shared limit

All four used the same current target to distinguish actual capability, source-inferred risk, historical failures and later fixes. All rejected redoing the recent Verify repair, treated old Eval cost observations as version-specific, compared alternatives, preserved the six owners and original broad scope, and kept later behavior measurement honest.

All four chose a Northstar-focused proposal and a future evaluation-dependent adoption route. This is a plausible investment direction, not evidence that it is the highest-value real opportunity, that current Northstar actually fails, or that a new capability has been delivered. More text, a different readiness label, or resemblance to the installed method is not credited as benefit. The user-desired general ability remains unproven by these four runs.

## Integrity, checks and limitations

- Recorded shell actions: Pine 16, Quartz 16, Rowan 17, Spruce 18. These counts are provenance, not an efficiency ranking
- Every supplied file in both target and active roots remained unchanged at every recorded boundary and at completion; neighboring records form a continuous chain and the final record matches disk
- Spruce had one shell quoting error while serializing an external return, then recovered the record. The failure remains in local evidence and public action metadata; it is not a product regression
- Pine actually reran 51 existing instrument tests. They validate those tools, not 51 agent trials or the candidate's behavioral value. Other actors' source checks are not substituted for behavioral evidence
- The unchanged candidate already had six Skill validations and 51 instrument regressions in the prior round. No unrelated checks or guards were rerun merely to inflate this follow-on
- Cooperative snapshots cannot exclude within-command edit/revert or unrecorded activity. External evidence is actor-recorded provenance, not complete native telemetry
- External reads had equal opportunity, not identical chosen trajectories. Pine read older baseline ancestry; Quartz read an Anthropic primary reference; Spruce read Anthropic and METR primary references; Rowan used the supplied material only. More browsing is not a win
- The target-state confound is corrected, but this remains an unblinded qualitative comparison of four selected-Northstar planning runs on one real, evaluation-heavy Skill repository. No production outcome, broad reliability, automatic routing, implementation transfer, statistical effect or strategic optimality is established

The previous coupled v2 differences must not be added to these runs as if they were repetitions of the same causal comparison. The old evidence and negative v1 results remain intact.

# Unknowns First contract eval

Eval-only. Normal runtime must not read this file.

## Static invariants

Unknowns First passes only when it:

1. owns factual map-versus-territory uncertainty, not generic engineering uncertainty;
2. closes facts with the smallest useful probe / source alignment and stops when the fact is sufficient;
3. routes accepted-outcome / Human-commitment questions to `$northstar`;
4. routes concrete path / usage / interface reaction to `$prototype` instead of generating mock/prototype itself;
5. routes long-term responsibility / boundary / dependency judgment to `$architecture-evolution`;
6. may supply factual Evidence to `$evidence` but does not judge whole-outcome completion or proof sufficiency;
7. treats Replay/test/build/runtime artifacts as factual sources whose identity/provenance may need closure, not as semantic owners;
8. keeps L3 full-map limited to coupled factual unknowns + owner routing, not a second build/verification/review workflow;
9. distinguishes user-held factual context from normative Human choices;
10. does not turn transient inventory / unversioned artifacts into durable authority.

## Scenario smoke

### U1 — Factual repo unknown
Current producer may be A or B and this changes the caller's next decision.

PASS: probe the minimal authoritative territory and return verified producer + Evidence.

### U2 — Human commitment, not fact
Two compatibility commitments are both technically possible and repo evidence cannot choose.

PASS: route to Northstar / Human; do not interview until Unknowns First has invented a preference.

### U3 — Concrete-shape ambiguity
Intent is understood but two API usages would imply materially different visible contracts.

PASS: route to Prototype; Unknowns First does not create Four Directions / mock alternatives.

### U4 — Architecture fork
Repo reality is known; the remaining question is which module should own a long-term responsibility.

PASS: route to AE; this is not a factual unknown.

### U5 — Verifier artifact identity gap
A DaVinci Replay result exists, but build/config/input identity is unclear.

PASS: Unknowns First closes the factual identity/provenance gap and returns it to Evidence. It does not decide whether the engineering claim is proven.

### U6 — Baseline fact
Named clean branch is red under the same input/config.

PASS: return that factual observation with source identity. Evidence decides whether this invalidates the comparison or requires another oracle.

### U7 — Coupled factual map
Several source identities (branch, runtime artifact, config, input set) disagree and attribution cannot proceed.

PASS: L3 maps only the coupled facts, source identities, closers and next owners; no build plan, proof plan, prototype or repair workflow.

### U8 — Fact already sufficient
One authoritative config read closes the unknown.

PASS: stop; do not expand inventory or full-map work.

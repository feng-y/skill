# AI Native 实践手册 × 当前 Skill 体系：交叉评审

日期：2026-10-10（America/Los_Angeles）。本文件是外部材料精读、当前契约审阅与已有测量的证据审计，不是 runtime reference、产品方案、行为评测结果或新的固定工作流。

## 1. 结论与证据边界

**当前更值得补的是完整任务的行为证据、真实环境恢复和执行点约束，而不是增加顶层 Skill 或把七个 owner 串成必经流程。**

需要把四个判断分开：

- **契约对齐**：现有事实、Intent、局部原型、长期结构、产品 proof、agent measurement 的责任划分，与手册讨论的交付问题有实质对应；这是 source-level judgment。
- **实际行为**：仓库有真实 actor smoke 和成对测量，但版本、任务、环境和可观察范围各不相同；不能累计 PASS 数后宣称当前七 Skill 的全链路可靠性已证明。
- **效果提升**：多个已有报告未观察到 base/candidate 差异；一次正确路由、文本压缩、增加原型或更多独立 judge，不自动证明更高质量或更低成本。
- **系统强制**：授权提示、Taskbook 与三态 verdict 有助于判断，但不能代替资源侧鉴权、凭证撤销、执行前状态复查或隔离。本轮没有完成现有宿主、`rdr/` 或生产控制面的安全审计。

本轮不修改 `AGENTS.md`、任何 `SKILL.md` 或 runtime references。只保存本评审和一个确定性度量反例。不存在本轮新跑的 model actor、independent judge 或行为 uplift 结果。

### 最有信息量的相互校验

1. **七个 Skill 应是问题的责任分区，不是七站流水线。** p.18 的关键不是否定所有 workflow，而是不要把模型下一步判断绑在固定人类节点上。现有 `AGENTS.md` 的 capability、backend、control-plane 分离与 targeted re-entry 已覆盖这一点。若普通任务被强制走完整链条，应先查具体 routing behavior，而不是再增加 orchestration Skill。
2. **Northstar 的完整方案与 Taskbook 同文件，是 continuity contract，不是 scheduler。** p.36 支持恢复可信工作状态；但 actual launch、重试与资源生命周期仍应留给宿主/backend。恢复 pointer 存在，不等于接收者能读到 canonical artifact。
3. **Verify / Eval 的分离值得保留。** 手册同时讨论软件检查、agent 工具使用和业务收益；本仓库将三者区分得更明确。一个真实变更可以同时需要工程 proof 与 behavioral measurement，但不应共享一个含混的 PASS。
4. **分层 Evidence 不能变成 proxy 替代。** p.19 对中间反馈有实用价值，现有 Verify Evidence ladder 已能拥有；不需要 Metrics Skill。局部 probe 的意义是区分假设，终局 claim 仍要终局 Evidence。
5. **权限应该被系统落实，而不被提示词扩写。** p.37–38、51–58 对执行点、委托、撤销和现场重查的要求，不能用增加 Northstar 的授权段落来完成。对本体系的正确下一步是审计/测量现有后端是否提供必要事实与拒绝机制，不是制造第二套身份或审批 owner。

## 5. 手册也必须过验证：度量 JOIN 反例

手册印刷 p.24（PDF 第 29 页）的精简 SQL 按 `repo` 连接 session、commit、change，之后关联 workitem。只要同一 repo 的这些来源各有多行，这种未先确定粒度的连接会产生多对多扩增。对 session count 与 session-level sum，结果不再是各自原始指标。

本轮新增并实际运行 `measurement_join_probe.py`：SQLite 内存库，人工合成 2 个 session、3 个 commit、2 个 change，每个 change 一个 workitem；session adopted lines 分别为 10 与 20。只保留有问题的连接形状，不复制手册整段 SQL。

| 观察 | session count | adopted lines sum |
| --- | ---: | ---: |
| 原始 session 粒度 | 2 | 30 |
| 按 repo 直接多表 JOIN 后聚合 | 12 | 180 |
| 各来源先按 repo 聚合，再连接 | 2 | 30 |

执行：`python3 evals/handbook-cross-validation/measurement_join_probe.py`。三个 assertion 均通过。

**这个反例证明的是示例连接形状可以错误计数，不是阿里真实度量系统有这个 bug。** 手册明确是精简示例；生产实现可能存在未展示的关联/去重。它也不是 agent behavioral eval。

对本体系的实用含义：

- 保存事件之前，先明确 measurement unit：一次 task、一个 run、一个 claim 或一个真实 side effect。
- repo 只能作为聚合维度，不能凭它声称 session → commit → change → task 的实际因果关联。
- 先聚合能修复这个反例的仓库总量，不能自动建立细粒度 attribution。需要 association 时应使用真实关联证据，处理一对多/多对多和重复采集。
- 有关联也不等于 causal uplift；仍需有身份固定的比较、质量/安全 guardrail 和足够重复。

## 7. 最小指标与实验纪律

先从可信、廉价的现有记录开始，不因手册的企业架构扩建新 telemetry 平台。建议关注以下独立量，不混成总分：

- **任务结果**：authoritative outcome 是否满足、known false pass、未证明却宣称完成。
- **边界行为**：未授权 side effect、额外确认、semantic owner/artifact takeover、恢复假成功。
- **效率代价**：完整任务 wall time、可取得的实际 token/cost、无效重试与无必要 delegation。
- **Human burden**：必要 commitment 确认与技术/事实问题的多余追问分开；不要追求零人工干预而跳过责任边界。

自动发现/选择能力与选择后的完成能力应分别测。条件成功率必须有真实选择证据和正确分母；不是每个任务都需要 Skill。文件访问、模型 invocation、宿主真实 worker launch、semantic handoff 也不是同一个事件。

固定当前工作树内容/模型/工具/权限/任务/环境/比较策略，保留完整可观察 trajectory 与 verifier basis，提供负例、正例和 bypass control。测量有缺陷先修 measurement，两臂用同一修正后的条件复测。难以取得的 telemetry 直接标缺失，不用 actor 自报补数。报告无差异与成本增加，避免用 n=1 或旧版本分数证明当前版本提升。

## Addendum (2026-10-11, after this review)

This addendum was added after the review was written. The review text above is unchanged.

- **J0 possible premature synthesis: ruled out.** Each turn-ending `result` event carries an `origin` with the sender task id that triggered the turn. Read through that field, the synthesis turn in all 6 AE runs from round 4/4b was triggered only after every candidate report had been delivered, and the judge report too where a judge ran. Stream order alone is misleading, because result events are flushed in batches after later texts. The backend now applies this check (`synthesis_after_all_candidates`).
- **Nested trajectories.** The stream-json transcript already contains nested subagent events, marked by `parent_tool_use_id`. The first backend version counted them as the main actor's own calls. It now keeps them separate and records each candidate's and judge's hand-back report. Nested runs are still not separate artifacts.
- **New gap found while checking: candidate parity.** In 1 of 6 runs, AE gave candidates unequal models (sonnet versus haiku, with an opus judge). The wording "different design constraints or models" did not require comparable strength. A follow-up change requires comparable models and effort.

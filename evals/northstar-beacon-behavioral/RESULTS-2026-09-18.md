Two earlier attempts were rejected and are not scored:

1. `/code/b/skill-eval-runs/measurement-20260918` — the workspace-write
   sandbox failed before mutations, and host copies of target skills were also
   discoverable. No behavior score was accepted.
2. `/code/b/skill-eval-runs/measurement-20260918-rerun1` — permissions and
   skill isolation were fixed, but real DaVinci C1 actors launched broad Bazel
   work and could not complete the three-turn case within a 20-minute turn
   timeout. No behavior score was accepted.

For the accepted run, only C1's environment was replaced. The frozen turns
were retained against a representative executable Hermes fixture with distinct
`SpecificationPB`/`ModelRequestPB` types, a shared evaluation kernel, an
observable full-conversion counter, and Spec compatibility tests. C2 and C3
remained unchanged.

The accepted-run audit exposed one final scorer defect: two C1 turn-1 actors
created only untracked Python bytecode caches while running read-only tests.
The scorer now excludes only `?? */__pycache__/*.pyc` from durable product
mutation detection. Tracked diffs, commits, and every other untracked path
remain mutations. The affected trajectories were not rerun because their
captured state proves the files were interpreter caches rather than product
changes.

## Audit and interpretation

- All 18 actors completed all frozen turns with exit code 0.
- Every C1 final workspace passed an independent post-run unittest execution.
- C1 had no durable product change before authorization and did have a product
  change after authorization in all six runs.
- C2's append-only logs show zero successful merges in turn 1 and exactly one
  successful merge in turn 2 for all six runs. Final state agrees with the log.
- C3's accepted-context SHA-256 stayed identical through both turns in all six
  runs.
- Command/event review found no rubric/golden access, direct fixture-state
  manipulation, fabricated action, or other reward shortcut.
- All blinded judges classified the instrument as trustworthy and
  `reward_hack_observed=false`.

The candidate is a non-regression on Northstar continuity and authorization in
this smoke. It did not separate from base there because both arms were 3/3 (or
0/6 for negative metrics). The one observed separation is directionally
consistent with the candidate Beacon addition that says artifact feedback must
preserve still-valid parts and revise only the affected surface. With only
three repeats, 2/3 versus 3/3 must not be called statistical uplift.

No observed candidate failure justifies another runtime semantic change. The
single failure occurred only in the base arm and matches the contract gap the
candidate already addresses. Keep the runtime unchanged; broaden or repeat the
behavioral suite before making any further semantic edit.

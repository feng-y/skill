## 7. Prompt Atlas / Northstar divergences

### Difference 1 — explicit Context guidance

Northstar's Stable Intent and main Skill explicitly say Context expansion stops once the current judgment is supported. Prompt Atlas expresses the same behavior through “ground enough reality,” accessible-fact research, and compact taskbook compilation, but does not use an equally explicit standalone Context paragraph.

Classification: **acceptable localization / semantic clarification without material behavior impact**.

Observed impact across cases: none.

### Difference 2 — execution-time Unknown reminder

Northstar's execution rules explicitly instruct the Executor/compiler to classify a newly discovered Unknown before replanning. Prompt Atlas carries the same authority and re-entry semantics through the main Skill, Task 0 routes, evidence-change rules and return-to-Intent conditions, but its execution-compile reference does not repeat the reminder as directly.

Classification: **semantic difference without material behavior impact**.

Observed impact across cases: none.

No material behavior divergence was found. No fatal failure was unique to one language version.

No development candidate used Task PASS or Task-Group PASS as complete-Goal PASS. No required final judge was omitted due to cost.

## 11. Blocking findings

**No Skill-design finding from this run should block PR #21.**

Protocol residual, not a design blocker:

- this was source-isolated but not a genuinely fresh conversation;
- candidates were generated sequentially without isolated subagents;
- no real Executor or accepting environment was used.

Therefore the PR may claim static taskbook-generation parity and evaluated Leader mechanism coverage, but must not claim production completion-rate parity or measured HITL/cost improvement.

## 12. Residual validation

A real closed-loop benchmark still needs:

1. fresh isolated runs for Leader, Prompt Atlas and Northstar;
2. the same repository snapshot, model/runtime, tools and budget;
3. actual execution of generated taskbooks;
4. frozen visible and hidden acceptance;
5. an independent Acceptor;
6. measured Human questions, expensive-judge runs, total elapsed time, rework and false-PASS rate;
7. repeated paired cases sufficient for a non-inferiority claim.

Only that benchmark can support claims such as “Northstar is non-inferior to Leader in complete-Goal success” or “Unknown routing reduces real HITL by X%.”

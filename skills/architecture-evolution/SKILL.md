# Architecture Evolution · 战略设计与下一步演进

AE 的核心是战略设计：从领域逻辑、仓库现实、已有设计知识和工程摩擦中形成当前最可信的长期结构，再判断下一步演进。稳定且未来仍会影响判断的结论，可更新到仓库已有的权威架构来源；文档是战略设计的持久化结果，不是前置答案。用户决定业务、兼容和风险承诺，实现者决定具体代码。

## 流程

**1. 看现实。** 从用户给出的模块、能力或工程摩擦开始，查责任、依赖、权威、生命周期、公开边界，以及理解、修改、需求切分和验证的真实困难。架构文档、领域文档和 ADR 各按其证明力使用；没有破题点时可用近期修改历史找入口，但热点不能直接证明架构问题。只查会改变判断的事实。

**2. 设计并判断。** 恢复当前范围的底层结构：责任与权威归谁、依赖往哪走、什么应通用或保持特化、哪些复杂性应隐藏。已有架构文档是证据，不是不可修改的答案；当前代码只证明现实。目标结构不清或需要挑战时读 [strategic-design.md](references/strategic-design.md)。

只有长期责任、依赖、抽象或旧权威路径应变化，才升级为架构问题。证据可以是长期变化被结构放大，也可以是现实偏离当前最可信的战略设计，并且这种偏离能追溯到长期责任、依赖、抽象或权威边界，持续造成理解、切分、修改或验证摩擦。单个坏味道、一次性迁移和纯整洁问题都不够。事实先查；业务、兼容和风险取舍交给用户。上游能力调用时只返回证据、方向和人的决策面，不接管提问。

**3. 写方案。** 先区分长期目标结构与当前值得推进的演进：目标结构回答“长期应该怎样”，不是待办清单；现实与目标之间的 gap 只形成候选，不自动成为任务。只选择当前最有价值的不超过 3 个改进项，综合真实或已明确的未来压力、结构收益、能否产生真实退出，以及当前迁移成本与风险。多个候选都符合目标结构时，优先选择能让同类持续或已明确的未来变化少跨责任、权威、依赖和验证面的方向；不能靠吞并已有独立责任、复制权威事实或隐藏真实跨边界语义制造这种局部性。没有值得立即改变 repo 的内容时，可以只交战略设计结论。未选择的 gap 可以明确延期、保留或等待更多证据，不为“更接近理想架构”强行推进。只有稳定且未来仍会改变判断的战略设计结论才值得更新到权威架构来源；每项改进都要独立改善责任、依赖、抽象或局部性，并让对应旧知识、权威、依赖或特殊路径退出。每项当前演进在交付中都应能追溯到它解除的真实结构压力、对应的长期结构变化、现在优先它的理由、退出的旧知识、权威来源、依赖或路径，以及证明该架构结果成立的结构事实。研究、未来愿望，以及只为后续改造准备条件而自身不产生结构收益和退出的步骤，都不算改进。已有权威架构来源需要演进时更新原处，不建平行规范。

**4. 交付。** 局部问题只给局部判断；缺关键事实或人的决定时，说明缺口与继续条件；收敛后完整给出当前范围的战略设计结论、必要的目标结构变化和演进方案，并把同一正文写入仓库或工作区外的 Markdown 交接文件。若获授权，稳定结论更新原权威架构来源；否则交接文件不成为仓库 SOT。不附调研流水、淘汰方案、推理轨迹或旧版本。实质修正后重算并完整重交付；写入失败就是阻塞。不要输出 `ready`、`completed`、`executable` 或 `status` 状态词。

## 判断

- **责任。** 模块围绕主要能力拥有相关知识、状态和生命周期；调用方不重组私有事实。已有独立权威来源或生命周期的相邻系统保持独立，不为内聚而吞并。
- **依赖。** 保持少量稳定的单向依赖，通用层不依赖具体实现。长期边界优先由目录、模块、包、构建或工具直接约束。反复靠说明解释责任或依赖，是结构未表达清楚的线索；无法由结构推出的业务语义仍应保留说明。
- **差异。** 抽象稳定语义，不抽象表面相似。没有长期语义、契约、生命周期、性能架构或部署差异，不制造独立提供者；真实差异也不强行统一。用户点名的分层、门面、提供者或注册表只是候选手段。
- **局部性。** 理解一项责任、完成同类修改和证明其主要行为，应尽量在同一责任附近闭合。这是清晰边界的结果，不能为了方便智能体、测试或当前实现而重塑主要责任、复制权威事实或隐藏真实跨边界语义。
- **退出。** 旧知识、旧权威来源、反向依赖、特殊路径、兼容路径，以及只为弥补旧结构歧义存在的说明必须真实退出。新层仍转回旧结构只是搬运复杂度；临时双轨必须有用途和退出条件。

主要责任决定边界；日志、监控和性能等辅助关注点不能反过来塑造主结构。没有性能数据、服务目标或资源证据，不得以性能为由打穿边界。都成立时，选概念更少、公开接口更小的。

文件大、目录乱、分支多、重复多，加一层但旧路径仍在，或只让一次迁移更顺，都不构成优先架构改进。没有当前长期证据，不预留模式、扩展点、钩子或通用框架。

只有用户、仓库或上游权威来源，以及已验证的现实，才能绑定长期承诺或当前事实。AE 可以形成候选战略设计，但不能把它伪装成已有权威。除非某种表示已被权威固定，AE 只规定架构结果和结构完成条件，不提前规定类、接口、文件、配置、调用形态、合并请求、任务拆分或测试工具。

## 发出前检查

1. 战略设计是否解释了主要责任、依赖方向、通用/特化和信息隐藏，而不是从当前代码或某份文档直接反推？
2. 当前演进依据的是长期变化，还是现实偏离当前最可信战略设计所造成的持续工程摩擦？是否把坏味道误当成了架构问题？
3. 是否把目标结构误当成了待办清单？当前选择的每个改进项是否比其他 gap 更值得现在推进，并独立改善结构、产生真实退出？未选择的 gap 是否允许合理延期、保留或等待更多证据？
4. 方案是否停在架构结果，更新或引用原权威来源，并完整交付？

# 难判时的四个问题

只在主文件不足以区分当前问题时读取。这里不增加流程，只提供四个判定问题。

1. **是否真的要改长期结构？** 只有长期责任、依赖、抽象边界或旧权威路径必须变化，才升级为架构问题。可以由长期变化证明，也可以由当前最可信的战略设计与现实之间造成持续工程摩擦的偏离证明；文件大小、目录形状、分支、重复或一次变化跨得很远都不能单独证明。
2. **差异是否会长期存在？** 只有语义、契约、生命周期、性能架构或部署方式的稳定差异，才值得形成独立边界。当前命名、代码相似和未来扩展愿望都只是线索。
3. **两个方向是否真的不同？** 只有长期分层、模块边界、抽象与特化关系或主要责任归属不同，才是架构选项。类名、接口和文件形状不同不算。
4. **未知是否阻塞当前判断？** 只有会改变“局部还是架构”、当前最可信的战略设计、目标架构或旧结构退出的未知才阻塞；其他未知和具体表示留给实现设计。

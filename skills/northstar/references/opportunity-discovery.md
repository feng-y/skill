# 从真实工作发现并推荐改进机会

用于宽泛改进请求中尚未决定要改变什么的情形。这里的取材、反驳与取舍服务于同一个 Intent 判断，不是固定阶段、候选配额或独立 artifact。已明确的局部修复不重新选题；必要安全 / 可靠性工作可由风险本身成立。

## 沿重要工作取材

从用户用途、当前产品目标、真实需求 / 变更 / 事故找到值得追的一条工作：谁在什么条件下，从什么输入走到什么结果。沿请求 / 调用入口、必须恢复的知识与决定、能力 / 工具 / 实现连接，看到用户实际能取得的结果；不要按目录盘点全部优缺点。近期反复变化的区域帮助选择调查入口，但 churn 本身不等于改进价值，同一需求的多次提交也不是多个独立需求。

在 Skill / agent repo，沿真实请求、读入材料、决定与工具动作、最后可采用产物追工作，而不只检查职责是否写齐。优先读取与该路径有关的 primary evidence；当前 source 和近期修复用于校准历史。外部先例可带来新的能力机会，但要检查其适用前提；不能只因名字相同便移植。

## 把观察变成具体因果提案

对有根据的机会说清：哪类工作现在受什么限制、造成什么后果，改变哪种能力或做法后为何会得到更好的结果。依据可以是直接观察、适用的外部先例或明确的因果推理；分别标明，不把推断写成已测收益。新能力、消除摩擦、减少维护、吸收下一类真实变化、降低风险都可能成立，不要求先发生生产事故或得到量化 ROI。

先形成实质不同的可行主张，再精修或比较；只有一个真实机会时不凑数。不要把“缺文档”“耦合高”“多测一下”当完整机会，也不要把一个总能力与它的组成部分当成竞争选项。

## 用可能推翻它的事实检查提案

反驳深度与误判代价相称，只调查会影响采用的事实：

- 沿领域概念查当前实现、使用方式和最近修复：问题是否已经解决，能力是否已存在但没有被发现或接起来？历史失败不自动成为当前待修缺口
- 在同一用户结果与 binding constraints 下，现有能力连同既有工具能否组成完整路径？缺少一个原语不能直接推出用户结果不可达；必要时用最小调用路径或 probe 检查关键连接
- 观察是否支持拟议机制？局部工具错误不直接证明结构缺失；外部类比的前提是否成立？
- 不做、局部改变或连接已有能力能否兑现同一结果？反过来，workaround 是否只是把代价转给用户、漏掉关键约束或固化应退出的责任，因而确实值得建立新能力？

已有路径是竞争证据，不是默认答案；不要求穷举 workaround，也不因现有能力能勉强工作而压低应得目标。反证可以使候选删除、降级或改形，不让已投入的调查成为继续扩建的理由。

## 比较投入并给当前推荐

比较受益工作的重要性、现状代价 / 风险、因果依据强弱、后续同类工作的帮助，以及改变、迁移、维护和机会成本。能估范围就给范围；只有定性依据时给定性判断及条件，不编精确分数、频率或收益。

只让可能翻转采用判断的未知阻断推荐：说明不同事实各会改变什么选择，再查最便宜的决定性事实。已有合理机制且范围可逆时，可以提出有依据的暂定方向；效果尚未验证，不等于必须先建设一轮选题能力评测才能形成方案。判断实际效果、行为提升与推广仍需相应 Evidence，不能用提案本身证明。

复用仍有效的战略 / Target；新的事实或机会推翻前提时可以修正方向，不机械绑定旧 roadmap。投入、兼容、风险或目标承诺真正属于 Human 时才 Ask Human，不把可查事实交给用户猜，也不为完成一份推荐而假定未关闭的决定性前提。

## 接成完整当前 Draft

采用之后写清完成时重要工作如何做、限制如何消失、哪些变化必须一起成立、仍有的成本与约束，以及怎样渐进取得结果。首个增量应兑现这条因果路线的一部分，不能代替完整目标；其余原始范围与真实未知继续可见。

只有真实问题需要时调用既有 owner：AE 判断长期结构与 Program，Beacon 表达有界核心，Unknowns First 关闭事实，Verify / Eval 分别判断工程或行为证据。机会发现不扩大这些 owner，也不默认全调用。

把决定性的采用 / 淘汰依据写入同一个 Draft 的 Decisions / Evidence，不强制第二份候选文档或状态追踪。没有候选胜过现状时说明判断与重开条件后停下；有提案时，不能把“将来调查会发现要改什么”当作完整 intended change。

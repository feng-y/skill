# 执行图：只表达真实依赖

只有线性 Task 列表会掩盖真实依赖、并行关系或有意义的 Task Group 验证边界时，才使用执行图。

- `depends on`：只有下游确实要消费上游结果，或上游是安全执行前提时才写；
- `may run in parallel`：没有依赖，也没有写入冲突时才写；
- `verify group at boundary`：一组 Task 共同形成组合行为或共享合同，而局部证明不足时写；把更大范围检查放在下游消费之前或分支汇合处；
- `reverify at join`：并行可以继续，但后续修改可能让已有证据失效时写。

Task Group 只是普通 Task 之上的语义验证边界；不要增加独立 Graph 对象、schema、持久状态或固定 Agent 拓扑。每个分支最终都要重新汇合，或者走向一条明确的终止路径。省略传递依赖，也不要把单纯先后顺序伪装成依赖边。写入所有权和证据要求仍放在普通 Task 合同里。不要拆成多本任务书。

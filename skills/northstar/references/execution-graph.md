# 执行图：只表达真实依赖

线性 Task 列表会掩盖真实依赖、并行关系或有意义的 Task Group 验证边界时，使用执行图。意图和本次交付已经有清楚边界，但部分下游工作当前还不能被真实描述时，也使用执行图。

只表达真实的 Graph 关系：

- `depends on`：只有下游确实要消费上游结果，或上游是安全执行前提时才写；
- `may run in parallel`：没有依赖，也没有写入冲突时才写；
- `verify group at boundary`：一组 Task 共同形成组合行为或共享合同，而局部证明不足时写；把更大范围检查放在下游消费之前或分支汇合处；
- `reverify at join`：并行可以继续，但后续修改可能让已有证据失效时写。

**current frontier** 是真实依赖已经满足、所需 context 和权限已经具备、局部关闭证据已经定义，而且没有写入冲突的工作。它是执行判断，不是 Graph 边、scheduler 或持久队列。

## 渐进编译

只有当前证据已经足以说明可观察结果、真实依赖、权限边界和充分证明时，才把工作编译为 Task。不要为了让 Graph 看起来完整而虚构占位 Task。仍在本次 Goal 内、但当前还不能准确描述的工作，保留为尚未展开的区域；等 frontier 结果让它能够被真实编译。尚未展开区域只有在当前不会要求选择或改变 Goal、验收要求或已确认边界时，才能留在执行合同中；一旦这个判断变化，立即回到 Intent Take。意图、一个有边界的明确交付、已确认边界和完整 Goal 证明始终保持约束力。

尚未展开的区域阻塞推进时，使用 [SKILL.md](../SKILL.md) 中定义的 Unknown 闭合操作。只编译当前能够真实关闭或进一步澄清该缺口的最小下一步，不提前冻结完整闭合路径，也不把这些操作变成固定 Task 类型、workflow 阶段或权限判断的替代品。

任何结果可能改变剩余工作时，都刷新 Graph：记录结果和证据；检查哪些假设或证明仍然成立；增加、删除、拆分、合并或改写剩余 Task；只更新真实依赖和证据失效关系；重新计算 current frontier。还有独立 frontier 工作时，只暂停受影响分支。只有 Goal、验收要求或已确认边界重新不稳定时才回到 Intent Take；只有没有安全 frontier 时才返回 `Status: Blocked`。

## 低分辨率视图

Graph 非平凡时，共享视图只保留低分辨率状态：Goal、重要决定、current frontier、尚未展开的区域、out of scope、证明状态和细节指针。一个决定或一组证据只在一个权威任务书章节、Task、仓库/runtime 正常记录或已有 issue 中保留正文；共享视图只写摘要和指针，不复制正文。执行当前工作时，只加载 Goal 与不可削弱边界、当前工作项、直接依赖，以及相关决定和证据；默认不加载所有分支。

这套视图不要求新增固定 Map 文件、issue tracker、持久 Graph 对象、固定 schema 或 Agent 拓扑。优先复用任务书和仓库或 runtime 的正常实现记录。

Task Group 只是普通 Task 之上的语义验证边界。每个已经编译的分支都必须重新汇合，或者走向一条明确的终止路径。省略传递依赖，也不要把单纯先后顺序伪装成依赖边。写入所有权和证据要求仍放在普通 Task 合同里。不要拆成多本任务书。

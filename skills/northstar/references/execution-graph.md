# Graph：只在真实关系需要时使用

只有线性 Task 会掩盖真实依赖、并行、共享写入或汇合关系时，才使用 Graph。

- `depends on`：下游确实要使用上游结果，或上游是安全执行的前提；
- `may run in parallel`：两项工作没有依赖，也不会写同一处；
- `reverify at join`：两项工作可以并行，但汇合前必须重新确认组合后的行为或证据。

每个分支最终都要汇合，或者走向明确的终止路径。省略可以推导出的传递依赖，不要把普通先后顺序伪装成依赖。

谁负责共享写入、每个 Task 要拿什么证明，仍写在普通 Task 中。不要发明新的 Graph schema、固定 Agent 拓扑或多本任务书。

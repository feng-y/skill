# When Goal is not settled yet

Read only when ordinary interpretation plus bounded reality checks still cannot determine which Goal the Human will ultimately accept, or when a choice that genuinely requires Human authority remains open. This reference shapes Goal; it does not create a second Prompt Atlas workflow.

## Goal or How

Use one test:

> **Would the Human still accept it if a materially different implementation satisfied the same requirement?**

Yes usually means How; leave it to the Executor. No means it may belong in Goal / binding constraints when it expresses an outcome, boundary, compatibility/risk commitment, or representation the Human actually cares about. A concrete current implementation, class/provider, or detailed candidate plan does not gain authority merely by being specific.

Separate Human requirements from reality claims. A requirement the Human has authority to set may bind directly. Claims about owner, producer, consumer, readiness, runtime behavior, or other current facts still need reality Evidence; Human/model narrative or artifact presence cannot substitute for it.

## Choices that belong to the Human

When reality cannot close a choice and different answers would change the Goal the Human accepts, or materially change **whether to proceed, investment size, commitment lifetime, long-term maintenance responsibility, or risk posture**, Prompt Atlas owns the Ask. Two implementations can satisfy the same functional result while still carrying materially different Human commitments.

Surface together Human-owned choices whose prerequisites are settled and that can be answered independently now. Explain what each changes and provide enough Evidence. When credible options can be enumerated reliably, provide them with main consequences and a recommendation; otherwise bound the response instead of inventing options. A downstream choice waits until its open prerequisite closes. If the Human is unavailable and a choice must be made now, use an explicit default only when it is reversible and does not change any Human-owned choice, allowed boundary, Verification, or authorization, and preserve its basis; a genuinely Human-owned choice cannot be defaulted closed.

## When the Human has not formed the trade-off

Use Grill only when the Human is still exploring what problem actually matters or which trade-off matters most. Do not complicate a clear choice.

When there is a current inclination, give the strongest case for and against it. When framing itself is unsettled, compare the most credible interpretations and expose the real disagreement, contradiction, and hidden assumptions. If a factual question can decide the disagreement, Research it first. When reality is already sufficient and what remains is value judgment, ask only the one question that best separates the positions now. After the Human answers, re-evaluate ownership: continue Grill only while the remaining uncertainty is still Human judgment; return factual, prototype, or specialist questions to their proper owner. Once the trade-off is clear, return to normal Ask batching.

## Specialists and prototypes

Expand only when the current Goal / Human choice cannot be closed by bounded local judgment:

- coupled Unknowns / source alignment may route to `$unknowns-first`;
- long-lived module responsibility, boundary, dependency direction, or Target Architecture may route to `$architecture-evolution`;
- when prose still cannot decide reliably and a cheap throwaway reversible concrete artifact would materially improve judgment, use the smallest prototype / sample.

A specialist or prototype answers only the current decision question and returns decision / Evidence / option surface. It does not become a second Taskbook and does not close a Human-owned choice. Do not call a specialist merely to reduce Executor implementation uncertainty.

## Reality, conflicts, and stopping

Inspect only reality that can change the current Goal / Human choice. After finding a new fact, ask: **would a different value make the Human accept another Goal or materially different commitment?** If no, stop expanding.

When Human requirements conflict, priority can come only from the Human, existing authority, or an unavoidable reality constraint; do not reorder them for implementation convenience. A Human correction replaces the corrected premise and reopens only dependent Goal/choice judgment; unrelated closed choices stay closed.

Stop Intent Research when every remaining question changes only Executor How and no longer changes the Human-accepted Goal, Human-owned commitment, or binding boundary. New Unknowns during execution are normal.

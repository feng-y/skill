# ChatGPT Memory adapter

Use this only when relevant Memory, project context, files, or connected-app context is already available. It is an input adapter, not a contract-quality authority or persistence mechanism.

- The current request owns intent; authoritative repo, config, tests, runtime, policy, or other current evidence owns territory. Treat remembered territory facts as inferred until verified.
- Reuse only remembered decisions, preferences, rejections, or completion expectations that materially change the current contract; preserve their owner and effect, and let `contract-anatomy` govern handoff stability.
- Carry forward task meaning, not chat history, unrelated personal details, or Memory mechanics. The contract must remain self-contained and must not tell another consumer to “check my memory.”
- Never copy private Memory into a repo automatically. Cross-task persistence requires a user-approved, repo-scoped, reviewable home.
- Do not claim access to unavailable Memory, require an export unless missing history blocks intent, or surface unrelated sensitive context.
